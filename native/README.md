# ActivityHeatmap

Нативное macOS-приложение: рисует heatmap активности прямо на рабочем столе – сетка 7×13
плиток, как contribution graph на GitHub, только про то, сколько времени ты реально
провёл за маком. Живёт в строке меню, данные берёт из системной базы Screen Time.

Никаких зависимостей: ни Node, ни Python, ни сторонних менеджеров виджетов. Один
`.app`-бандл на Swift/SwiftUI.

- Как это устроено внутри – [ARCHITECTURE.md](ARCHITECTURE.md)
- Что проверено, а что нет – [STATUS.md](STATUS.md)

## Что умеет

- **Виджет на рабочем столе.** Стеклянная карточка ниже окон приложений, но выше обоев.
  Перетаскивается за шапку, позиция запоминается.
- **Тултип по наведению.** Дата, суммарное время за день, топ-3 приложений и сайтов.
- **Настройки** в отдельном окне: что учитывать, цвет, размер, язык.
- **Два языка:** русский и английский, плюс режим «системный».
- **Своя история.** macOS хранит статистику всего несколько дней – приложение копит её
  само и держит 91 день.

## Сборка

Нужны только Command Line Tools (`xcode-select --install`). Полный Xcode не требуется.

```bash
cd native
./build.sh            # debug-сборка
./build.sh release    # release-сборка
```

Результат – бандл `ActivityHeatmap.app` в этой же папке:

```bash
open ActivityHeatmap.app
```

Приложение не показывается в Dock – оно живёт значком в строке меню.

## Первый запуск: два обязательных шага

### 1. Стабильная подпись – ДО выдачи доступа к диску

Full Disk Access в macOS привязывается к подписи приложения. Без своего сертификата
`build.sh` подписывает бандл `ad-hoc`: такая подпись меняется при **каждой** пересборке,
и выданное разрешение слетает.

```bash
./make_cert.sh
```

Скрипт ничего не делает сам – только печатает пошаговую инструкцию. Создание сертификата
трогает связку ключей, это должен сделать человек. Выполни инструкцию один раз в Keychain
Access, затем пересобери:

```bash
./build.sh
```

В выводе должно появиться:

```
using stable identity: ActivityHeatmap Dev (<отпечаток сертификата>)
```

Проверить результат:

```bash
codesign -dvvv ActivityHeatmap.app
```

Ожидается `Authority=ActivityHeatmap Dev` и флаг `runtime` в строке `CodeDirectory`.
Если видишь `Signature=adhoc` – сертификат не подхватился, доступ к диску будет слетать.

> Если сертификат случайно создан дважды, `codesign` не сможет выбрать между тёзками.
> Сборка подписывает по отпечатку, а не по имени, и закрепляет выбранный в
> `.signing-identity` – поэтому дубликаты не ломают сборку, но лишние можно удалить в
> Keychain Access.

### 2. Full Disk Access

Без этого разрешения приложение не может прочитать базу Screen Time и вместо сетки
покажет инструкцию.

1. Системные настройки → Конфиденциальность и безопасность → Полный доступ к диску.
2. «+» → добавь `ActivityHeatmap.app`.
   (Либо нажми «Открыть настройки системы» прямо в окне настроек приложения – кнопка
   открывает нужный экран.)
3. Включи переключатель напротив приложения.
4. Перезапусти приложение: значок в строке меню → «Выход», затем `open ActivityHeatmap.app`.
   Процесс, запущенный до выдачи прав, их не подхватывает.

Индикатор в окне настроек показывает текущее состояние доступа и обновляется каждый раз,
когда окно становится активным.

## Настройки

Значок в строке меню → «Настройки…».

**Главное**

| Параметр | Что делает |
|---|---|
| Виджет включён | Показывает/прячет карточку на рабочем столе |
| Запускать при входе | Системный Login Item (`SMAppService`), обратимо тем же тумблером |
| Доступ к данным | Индикатор Full Disk Access + кнопка перехода в системные настройки |
| Цвет плиток | Пять пресетов; фирменный фиолетовый использует подобранную вручную палитру, остальные генерируются |
| Жидкое стекло | Насыщенный фон и светлые кромки. Выключенный даёт спокойный плоский вариант |
| Размер виджета | Единый масштаб 50–150 %. Ширина и высота меняются вместе |
| Язык | Русский / English / Системный. Применяется сразу |

**Приложения и сайты**

Списки того, что попадает в статистику: приложения по bundle id, сайты по домену. Есть
поиск и кнопка «Добавить вручную» – на случай, если нужного пункта ещё нет в списке.

Список кандидатов наполняется тем, что реально встречалось в твоих данных: приложение
ведёт отдельный каталог идентификаторов и помнит их дольше, чем сама macOS.

## Управление виджетом

- **Перетащить** – потянуть за шапку (строку «Активность» с пилюлей). Клетки сетки
  остаются под мышью для тултипов, поэтому тянуть можно только за шапку.
- **Вернуть на место** – двойной клик по шапке.
- Позиция хранится в `position.json` и переживает перезапуск.

## Файлы данных

```
~/Library/Application Support/ActivityHeatmap/
  activity.json    накопленная история активности (91 день)
  catalog.json     каталог встречавшихся приложений и сайтов
  settings.json    настройки
  position.json    смещение окна виджета
  activity.log     технический лог
```

**`activity.json` и `catalog.json` – единственная копия того, что macOS уже удалила
из своей базы.** Система хранит подробную статистику всего несколько дней, поэтому
приложение накапливает её самостоятельно. При любой ошибке чтения файлы намеренно не
перезаписываются, запись атомарная. Хочешь бэкап – просто скопируй их.

Из этого следует, что сетка заполняется постепенно: первое время правая часть живая,
а левая пустая. Это нормально и лечится только временем.

## Диагностика

Проверить доступ к базе, не открывая интерфейс:

```bash
./.build/debug/ActivityHeatmap --check-fda
```

Прогнать встроенные тесты (447 проверок, без UI):

```bash
./.build/debug/ActivityHeatmap --self-test
```

Посмотреть, что приложение записало:

```bash
python3 -m json.tool ~/Library/Application\ Support/ActivityHeatmap/activity.json
tail -20 ~/Library/Application\ Support/ActivityHeatmap/activity.log
```

**Виджет не реагирует на мышь.** Проверь, не запущен ли Übersicht или другой менеджер
десктопных виджетов: их полноэкранное окно лежит выше уровня рабочего стола и
перехватывает события мыши первым.

**Виджет показывает «Считаю активность» и не меняется.** Значит агрегация не завершилась –
смотри последние строки лога.

## Удаление

1. Выйди из приложения: значок в строке меню → «Выход».
2. Если был включён автозапуск – **сначала** выключи тумблер «Запускать при входе»,
   иначе Login Item останется зарегистрированным в системе после удаления бандла.
3. Удали бандл: `rm -rf ActivityHeatmap.app`.
4. Удали данные, если история больше не нужна:
   `rm -rf ~/Library/Application\ Support/ActivityHeatmap`
5. Системные настройки → Полный доступ к диску → убери запись кнопкой «−».
6. Сертификат `ActivityHeatmap Dev` в Keychain Access – удали, если он больше ни для
   чего не нужен.
