# ActivityHeatmap.app – технический контракт

Единый источник правды для всех, кто пишет части приложения. Если твоя задача расходится
с этим документом – не выдумывай, сообщи руководителю.

## Что делаем

Самостоятельное macOS-приложение, рисующее heatmap активности прямо на рабочем столе.
Заменяет связку Übersicht + `index.jsx` + `aggregate.py`. Референс лежит рядом:
`../activity-heatmap.widget/` – там рабочая логика и дизайн, **логику оттуда переносим,
код не копируем** (Python → Swift).

**Стек решён: Swift/SwiftUI. Не Tauri, не webview.** Проверено: SwiftUI, AppKit и SQLite3
собираются одним Command Line Tools, полный Xcode не нужен.

## Форматы данных

### Снапшот активности

Тот же формат, что у Übersicht-версии – намеренно, чтобы переиспользовать тестовые данные
и иметь возможность сверить два движка на одном входе.

```swift
struct ActivitySnapshot: Codable {
    let generated: String              // ISO-8601, локальное время
    var days: [String: DayStats]       // ключ – "YYYY-MM-DD" по локальному календарю
}

struct DayStats: Codable {
    let t: Int                         // секунды активности за день
    let top: [[TopEntry]]              // ровно ≤3 элемента, отсортированы по убыванию
}
// top сериализуется как [["Claude", 8400], ["VLC", 2700]] – пара имя/секунды
```

Живой пример на диске:
`~/Library/Application Support/Übersicht/widgets/activity-heatmap.widget/activity.json`

### Каталог идентификаторов

Дефект первой редакции контракта, найден на стадии 4: в `top` лежат только отображаемые
имена (`"Claude"`, `"VLC"`), а фильтры в настройках оперируют исходными идентификаторами
(`com.anthropic.claudefordesktop`). Восстановить одно из другого нельзя, поэтому список
«что встречалось в данных» в окне настроек строился эвристикой.

Агрегатор обязан вести отдельный каталог сырых идентификаторов:

```swift
struct CatalogEntry: Codable {
    let id: String        // bundle id для приложений, домен для сайтов
    let kind: Kind        // .app | .site – из стрима, НЕ угадывать по виду строки
    let name: String      // отображаемое имя на момент записи
    let seconds: Int      // суммарное время за окно наблюдения, для сортировки
    let lastSeen: String  // "YYYY-MM-DD"
}
```

Пишется в `catalog.json`, накапливается так же, как история (91 день), и переживает
очистку knowledgeC.db. Окно настроек берёт список кандидатов ТОЛЬКО отсюда – никаких
эвристик по виду строки.

```swift
struct Settings: Codable {
    var widgetEnabled: Bool = true
    var launchAtLogin: Bool = false
    var mode: FilterMode = .deny        // .deny | .allow
    var apps: FilterLists               // allow/deny, ключ – bundle id
```

Начальные значения брать из `../activity-heatmap.widget/config.json` – там уже заполнены
списки и имена под реальные приложения пользователя.

## Алгоритм агрегации – переносить точно

Это не «примерно как раньше». Каждый пункт ниже – следствие найденной на реальных данных
проблемы, отступление от него ломает цифры.

1. **Источник.** `~/Library/Application Support/Knowledge/knowledgeC.db`, таблица `ZOBJECT`.
   База заблокирована системой – **копировать в temp вместе с `-wal` и `-shm`**, читать копию.

2. **Время.** `ZSTARTDATE`/`ZENDDATE` – Core Data timestamp, offset `978307200` от Unix.

3. **Домены сайтов НЕ лежат в `ZVALUESTRING`.** Там bundle id браузера. Настоящий домен –
   джойном `ZOBJECT.ZSTRUCTUREDMETADATA → ZSTRUCTUREDMETADATA.Z_PK`, поле
   `Z_DKDIGITALHEALTHMETADATAKEY__WEBDOMAIN`. Проверено: 0 NULL на 4296 строках.

4. **Итог дня** = union интервалов `/app/usage`, **пересечённый с периодами разблокированного
   экрана**. Заблокированные окна: `/device/isLocked` с `ZVALUEINTEGER = 1`.
   Без вычета блокировки всегда включённый мак даёт ровно 86400 с каждый день.

5. **Только foreground.** `/app/webUsage` тикает и для фоновых вкладок (закреплённая
   `desktop.docker.com` накрутила 46 ч за 6 дней). Поэтому:
   - общий итог дня считается **только** по `/app/usage`;
   - время домена = его интервалы ∩ интервалы `/app/usage` его браузера ∩ разблокировано.

6. **Браузеры не показываются в топ-3.** Браузер = любой bundle id, встреченный в
   `/app/webUsage`. Его время идёт в итог дня, но в разбивке его представляют домены –
   иначе время задваивается.

7. **Union, а не сумма.** Время каждого приложения – объединение его интервалов.
   Наивная сумма давала Safari 27.8 ч в сутках.

8. **Полночь.** Интервалы режутся по локальным суткам и попадают в оба дня – и для
   разбивки, и для итога.

9. **Порог.** Дни короче `minSeconds` не попадают в снапшот.

Эталонная реализация со всеми деталями: `../activity-heatmap.widget/aggregate.py`.

## История – критично

macOS чистит `knowledgeC.db` очень быстро: на машине пользователя в базе лежало **6 дней**.
Сетка на 13 недель из одной базы не заполнится никогда.

Поэтому приложение ведёт свою историю: при каждом обновлении мержит свежие дни в
`activity.json` и держит 91 день. Дни, ещё присутствующие в базе, перезаписываются;
более старые доживают в файле.

**При любой ошибке (нет доступа, сбой чтения) файл не перезаписывать.** Это единственная
копия того, что система уже удалила. Запись только атомарная: во временный файл рядом,
затем `FileManager.replaceItem`.

## Палитра

Рампа из 5 оттенков строится из одного акцентного цвета: акцент переводится в OKLCH, берётся
его **hue**, по нему проходит фиксированная кривая
`L = [.95, .86, .75, .62, .48]`, `C = [.025, .09, .13, .14, .12]`.
Chroma загоняется в sRGB бинарным поиском. Ахроматичный акцент (chroma < 0.02) → серая рампа,
а не случайный тон. Битый акцент → откат на `#9974f7`.

Эталон с проверенными числами: функции `hex_to_hue_chroma` / `oklch_to_hex` в `aggregate.py`.
Контроль: `#9974f7` → hue 293.6 → `#efecfe #d3c8ff #b29df8 #8b73d2 #624e9a`.

Уровень клетки – квартили по непустым дням (25/50/75 %), а не абсолютная шкала.

## Дизайн

**Виджет** – как сейчас в `index.jsx`: стеклянная карточка, шапка «Активность» + пилюля со
счётчиком дней, сетка 7×13 (понедельник сверху, последняя колонка – текущая неделя),
скругление клетки ≈ 0.2 от размера, зазор ≈ 0.23, легенда «Меньше … Больше», тултип с датой,
суммой и топ-3. Перетаскивание за шапку, двойной клик – сброс позиции.

**Окно настроек** – по макету `~/Downloads/tile_activity_design_maket.html`, три экрана:
главное окно, список приложений/сайтов, трей-меню. Токены оттуда:

- акцент `#9974f7`; чернила `rgba(30,25,50, .9/.85/.75/.5/.45)`
- поверхности `rgba(255,255,255, .5–.85)`; границы `rgba(30,25,50, .12/.15/.25)`
- статусы: доступ есть `#4fc9a8`, доступа нет `#f7a05f`
- радиусы 8/12/16/20/26/999; кегли 11/12/13/14

Внимание: текстовый дизайн-промпт требует «без теней и градиентов», но сам макет содержит и
тени, и градиенты, и `backdrop-filter`. **Приоритет у макета** – он совпадает со стилем
виджета.

## Риски – проверено на живой сборке 19.07.2026

1. **Full Disk Access привязан к подписи.** ОТКРЫТО. Подтверждено: приложение получает
   `SQLITE_AUTH (code=23)` без гранта, обхода нет. Ad-hoc подпись меняется на каждой сборке
   и разрешение слетает – нужен стабильный самоподписанный сертификат ДО первой выдачи FDA
   (`make_cert.sh`). Пока сертификата нет, `build.sh` предупреждает и подписывает ad-hoc.

2. **Реальное стекло – РАБОТАЕТ.** `NSVisualEffectView` с `.behindWindow` на уровне рабочего
   стола действительно размывает обои; отличие от плоской заливки видно глазом. Это то, чего
   `backdrop-filter` в вебвью не умеет в принципе (ему нечего сэмплить в прозрачном окне).
   **Виджет строить на `NSVisualEffectView`, а не на полупрозрачной заливке.**

3. **События мыши – РАБОТАЮТ, но только при двух условиях.** Оба обязательны:

   - **Уровень выше иконок.** На `desktopIconWindow - 1` мышь не доходит НИКОГДА: окно
     рабочего стола Finder (layer `-2147483603`) растянуто на весь экран и перехватывает
     события первым. Рабочее значение – `desktopIconWindow + 1`. Проверено: hover
     срабатывает и логирует координаты клетки.
   - **Окно размером с карточку, а не во весь экран.** На рабочем уровне полноэкранное окно
     перехватывало бы все клики по пустому столу (ломая выделение рамкой и контекстное меню)
     и закрывало бы иконки Finder. Окно сжато до контента и позиционируется от левого
     верхнего угла.

   Оба исправления уже внесены в `DesktopWindow.swift`.

4. **Конфликт с Übersicht.** У работающего Übersicht есть окно на `layer = -1`, растянутое
   почти на весь экран – оно НАМНОГО выше нашего десктопного уровня и перехватывает мышь.
   Пока Übersicht запущен, hover в нативном виджете не работает. Это не дефект натива:
   после замены Übersicht проблема исчезает. **Для тестирования натива Übersicht гасить.**

5. **Drag пока не подтверждён.** В том же прогоне, где hover дал 4 события, синтетический
   `left_click_drag` не залогировался. Причина не выяснена: возможно, инструментация ловит
   не тот жест, возможно – особенность синтетических событий. Перетаскивание виджета
   обязательно (есть в Übersicht-версии), поэтому **стадия 3 должна проверить drag живой
   мышью и починить, если он не ловится.**

## Ловушки, стоившие отладки – не наступать повторно

1. **`@Published` + синхронная отрисовка = залипание вида.** Публикатор `@Published`
   срабатывает в `willSet`, то есть ДО фиксации значения. Если подписчик синхронно вызывает
   что-либо, вынуждающее отрисовку (`setFrame(display: true)`, `layoutSubtreeIfNeeded`,
   чтение `fittingSize`), SwiftUI пересчитывает тело со СТАРЫМ состоянием и считает
   обновление выполненным – повторной отрисовки не будет никогда.

   Симптом: виджет вечно показывает «Считаю активность», хотя модель давно в другом
   состоянии и это видно в логах. Лечится `.receive(on: DispatchQueue.main)` в подписке –
   перенос на следующий виток цикла, когда значение уже зафиксировано. **Не убирать.**

2. **Подписывать только по отпечатку сертификата, не по имени.** Мастер в Keychain Access
   не предупреждает о повторном создании, и два одноимённых сертификата валят `codesign`
   с `ambiguous (matches ... and ...)`, оставляя бандл неподписанным. Выбранный отпечаток
   закреплён в `.signing-identity`, потому что Full Disk Access привязан к хешу листового
   сертификата: молчаливое переключение на другой одноимённый сертификат отзовёт доступ.

3. **`security find-identity -v`** не показывает самоподписанные сертификаты без явного
   доверия (`CSSMERR_TP_NOT_TRUSTED`), хотя подписывать ими можно. Флаг `-v` в детекте –
   причина молчаливого отката на ad-hoc.
